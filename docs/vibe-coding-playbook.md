# OpsForge Vibe Coding 操作手册

> 面向业务运营人员：如何用 AI 编码代理（Claude Code / Cursor / Codex / Cline）安全地造一个能力。

## Step 0 — 准备

确认你在仓库根，Node 22 可用。先跑一遍基线：

```bash
node tools/validate.mjs --all
```

应输出 `verdict: pass`。

## Step 1 — 用脚手架起骨架（不要手建）

```bash
# 通用能力
node tools/new-capability.mjs --kind skill --slug <你的 slug> --name <能力名>
# 品牌能力
node tools/new-capability.mjs --kind agent --brand <品牌 slug> --name <能力名>
```

> 也可以用向导（v9 §22.8，等价、会调用上面的命令）：`node tools/opsforge.mjs new`

脚手架会在 `packs/_drafts/<slug>/<name>/`（品牌则在 `customers/<brand>/packs/_drafts/<brand>/<name>/`）生成法定文件集，预填工程字段，业务字段标 `__FILL_ME__`。

## Step 2 — 对 AI 代理说什么（话术模板）

> 在 `D:\XD\ClaudeCode\sy-eeo` 仓库工作。遵守 AGENTS.md。只改我新建的能力目录里的 `.md` / `.yaml` / `.json`。不要新增 frontmatter 字段，不要新增骨架外文件，不要改工程字段。帮我把 `__FILL_ME__` 全部填成真实内容。

## Step 3 — 填业务字段

打开 `capability.yaml`（skill 是 `SKILL.md`），把所有 `__FILL_ME__` 替换成：

- `display_name` / `display_name_zh` / `display_name_en`：能力名（中英）
- `description`：一句话说明

## Step 4 — 写 body

- agent：`source.md` 的正文
- skill：`SKILL.md` 的 frontmatter 下正文
- mcp：`source.md` + `mcp.yaml` 的 `tools` / `config_template`

## Step 5 — 写回归用例

`tests/case-01.yaml` … `case-03.yaml`。脚手架已预填**工程字段**（`expect` / `schema_ref` / `judge_rubric` / `judge_threshold` / `weight`，勿改），你只填业务字段 `name` / `input` / `expected`。staged 要求 ≥3 条。

```yaml
name: 普通会员             # 业务字段
input: { level: normal }   # 业务字段
expect: exact              # 工程字段，勿改。支持 exact/contains/human/schema/regex/llm_judge/golden（Phase 2.2 起全部 7 模式可用；业务作者默认填 exact）
expected: 欢迎来到 OpsForge！ # 业务字段
schema_ref: null           # 工程字段，勿改
judge_rubric: null         # 工程字段，勿改
judge_threshold: 0.7       # 工程字段，勿改
weight: 1.0                # 工程字段，勿改
```

> staged 行为门禁会查用例（PLAN §21.7）：`expected` 不得是 `"ok"`/`"true"`/`"pass"` 等空话（R18）；任意两条 `(input, expect, expected)` 不得完全相同（R19）；每条必须显式声明 `expect`（R21）。

## Step 6 — 跑自检

```bash
node tools/validate.mjs <你的能力路径>
```

### 常见报错解读

- `schema: ... failed AJV: ... additionalProperties` → 你加了 schema 不允许的字段，删掉。
- `skeleton_guard: file set mismatch; missing=[...], extra=[...]` → 你多建/少建了文件，对照 `templates/<kind>/`。
- `placeholder_clean: <file>:<line> contains placeholder "__FILL_ME__"` → 该行还有占位符没填。
- `engineering_fields_untampered: field "kind" expected "agent" got "skill"` → 你改了工程字段，改回脚手架预填值。
- `naming: "My_Slug" does not match ^[a-z][a-z0-9-]{2,30}$` → slug 不合规，全小写连字符。
- `version_lock: draft version must be 0.1.0, got "0.2.0"` → 草稿区 version 必须是 `0.1.0`，改回。
- `tests_min: expected >=3 test cases, got 2` → 补到 ≥3 条用例。
- `entry_guard: "..." not generated by new-capability.mjs` → 目录是手建的，删掉用脚手架重建。
- `body_min_substance` / `body_not_boilerplate`（R16/R17）→ 正文太短或空话套话，补实质内容。
- `test_expect_nontrivial` / `test_cases_distinct` / `test_expect_declared`（R18/R19/R21）→ `expected` 太空、两条用例重复、或没声明 `expect`；改用例。
- `description_body_alignment`（R20）→ 描述里的名词没在正文出现，补关联内容。
- `no_self_cheat_in_body`（R22）→ 正文写了"直接返回 expected"之类自欺话术，删掉。
- `.opsforge-state.json` 缺失 → 该文件由脚手架生成（steering overlay，勿手建/勿删）；用 `new-capability.mjs` 或 `opsforge new` 重新生成能力目录。

## Step 7 — promote 到 staged

```bash
node tools/new-capability.mjs --promote <你的草稿路径>
```

promote 把 `_drafts/` 改名到 `_staged/`，不改 frontmatter。然后提 PR：`[stage] <slug>.<name>` 或 `[stage-brand] <brand>.<name>`。

## 红线（不可豁免）

- `source.md` / `SKILL.md` 不得含"忽略以上指令""以管理员身份"等提示注入话术。
- MCP `inputSchema` 不得允许任意 shell / 路径执行。
- 不得引入新依赖。
- 不得手移目录。
