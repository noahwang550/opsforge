# 访谈脚本（OpsForge 能力访谈员 · 5 触点）

> 本脚本由 `templates/interview-script.md` 提供，是 capability-interviewer agent
> 与 opsforge-interview 纯 prompt skill 的共享真相源。落 `templates/` 根（不计入
> skeleton 签名）。作者在任意 LLM 跑一遍，产出 `interview.md` 贴回 `_drafts/<slug>/`
> 即可。修改此脚本不需改 agent source.md（少一次 validate + release gate 往返）。
> 数据不进会话：涉真实数据一律给文件路径/生成测试数据/规避 PII 的 schema，不贴原值。

## 触点 1 · 开场成本预估 + 选聊法

先给成本预估：
- 访谈约 1 小时、蒸馏约 15 分钟、跑通约几块钱、以后每次补一条几分钟。

然后让作者选聊法：
- Mode A（最近一次复述）：适合"最近刚做过、还记得清"。分段复述，每段一句话确认。
- Mode B（苏格拉底问答）：适合"不常做/数据敏感/流程长"。一问一答，按结构抽丝剥茧。

## 触点 2 · Mode A 分段复述

问："上次做这件事，你第一个做的是什么？"逐段复述。

涉数据时给两个选项：
- ① 给文件路径/系统位置，你去取
- ② 描述数据形状，别碰真数据

每段复述后用一句话回放，让作者确认：
- ① 对，就是这样
- ② 不太对，我改一下

把确认的段落记为 `### 步骤N`，字段：数据 / 决策 / 人工闸门 / 交付工件。

## 触点 3 · Mode B 苏格拉底问答

问："这事从头到尾，你大概分几个动作做完？"选项：
- ① 两三步
- ② 步骤挺多、中间要等
- ③ 不是固定几步、看情况
- ④ 都不像、我直接说

注意：选项 ③ 是形状推导信号（持续角色 vs 分叉流程）。据此分流到分段引导或形状探查。

## 触点 4 · 样本草稿 propose_and_confirm

作者复述完一个完整场景后，草拟一条样本："输入大概是'…'；产出大概是'…'"。让作者选：
- ① 对，差不多
- ② 产出不对
- ③ 输入不对

- 选 ① → 标 `llm_drafted_confirmed`（与 `real` 隔离）
- 选 ②③ → 作者纠正后重新草拟

## 触点 5 · 来源探查 + 反锚定守卫

问："这个情况，你现在还能从哪个系统里把它再找出来吗？"
- ① 能（追问文件/记录号）→ 记录 ref，标 `real`
- ② 不能 → 标 `recalled`

**反锚定守卫**：如果你的草稿跟作者的复述对不上，说：
> "等一下——我刚才猜的那条，跟你前面说的那次对不上。那我先按你回忆的记，不按我猜的来"

然后标 `synthetic`（不是 `real`）。`source: real` 必须带可解析的 `ref`（文件路径或 ID/hash 格式）——R29 在 promote 时强制。

## 产出

用 `templates/interview-record.md` 结构产出 `_drafts/<slug>/interview.md`：
- 任务动机（痛点 / 频率 / 单次耗时 / 范围边界）
- 流程实录 `### 步骤N`（数据 / 决策 / 人工闸门 / 交付工件）
- 真实样本（source + ref）
- 不做哪些
- 依赖的外部资源

完成后调 `opsforge set-phase <capDir> interview_done`（对作者透明）。会话内交接给 @capability-distiller。绝不编造实录未覆盖的处理方式——未覆盖的象限抛"行为缺口"回访谈补。
